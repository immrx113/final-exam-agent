# M2 需求与验收

## 阶段目标

学生打开一门课已导入的材料后，可以按章节了解学什么，按真题频次判断先关注什么，并从任一统计数字逐题查回原文。第一门验收课程为《数据库原理》。学习顺序、待办、笔记和课程知识导出留到 M3，视频留到 M4。

2026-11-24 需求讨论后进入开发。以下条目用于设计和执行验收用例。依据范围见[知识库索引](index.json)。

## 学生能完成的操作与验收条件

| 编号 | 操作或样例 | 预期结果 |
| --- | --- | --- |
| M2-01 | 导入一份课件和一份讲义，两份均讲“函数依赖”，讲义里还有一道练习题 | 按课程、章节浏览知识点。“函数依赖”只出现一项，有简要说明和两个可打开的教学出处。讲义练习不进入真题频次。 |
| M2-02 | 导入三份有效样卷。“函数依赖”只在卷甲考了四题，“关系代数”在三份卷各考一题 | 排行榜依次显示“函数依赖 4 题 · 1/3 份卷”“关系代数 3 题 · 3/3 份卷”。同题数优先覆盖卷多者，再按章节与知识点顺序。 |
| M2-03 | 一题题干重复提到一个概念，解题还需要第二个概念；另一大题有两个独立编号且可独立作答的小问 | 前一题对两个实际考查的概念各计一次，题干中仅顺带提及的概念不计。后一题按小问计，父题不额外计入。跨页续题保留同一题号和各页证据。 |
| M2-04 | 从排行榜点开“函数依赖”，逐条查看命中题 | 能列出四道不同的题，每条都有卷名、题号和位置。点击可打开对应的原页、行或原图；教学出处也可单独打开。列表题数和不同卷数能复算出排行榜数字。 |
| M2-05 | 改名重传同一份卷；另给一组无法确定属于几份卷的扫描图 | 内容完全相同的试卷仅计一份。分组不明或疑似同卷的材料单列，展示文件、原因与预览，待归属明确后才纳入分母。本阶段建议只交付疑义清单，人工改组与回写另议。 |
| M2-06 | 分别使用只有教学资料的批次、有有效卷但某知识点未考的批次，以及含模糊扫描题的批次 | 前者保留章节并显示“暂无试卷统计”；有有效卷时，频次和章节目录只列命中题数大于零的知识点，总数与可见项一致。全为零时提示暂无已确认命中。已确认归属、至少有一道可辨识题目的卷计入 N。模糊题的存疑关联单列并链接原页，其余可靠命中照常统计。 |
| M2-07 | 卷中考到课件未收录的概念 | 有明确题意和证据时在“待归类”中展示概念和原题，可按有效命中计数。只能猜测关联时列为“待核对”，暂缓计数。 |
| M2-08 | 发布一次分析，再追加试卷重新分析；模拟分析超时、返回越界证据、同批重试和缓存不可用 | 新结果就绪前仍可看上次完整结果。非法引用不能进入正式结果；同批重试不增加题数。成功后目录、排行、明细一起切换，原有明确匹配的知识点沿用标识。缓存不可用时仍能从数据库读取相同结果。 |

## 建议开发顺序

1. **先定人工答案。** 复用 M0 已有的来源定位与模糊题样例，另制三份可分享的样卷。先标出每卷、每题、独立小问、命中概念、原文位置与应暂缓计数的原因，再运行分析。
2. **先贯通一个知识点。** 从 M1 批次读取片段和位置。Python Agent 先从课件、资料返回章节与知识点候选，再从试卷返回题目、命中和证据。Java 核对批次、来源和候选标识。先让学生能从一个知识点打开讲义和真题，再扩展分题与归并。
3. **由 Java 统一统计与发布。** 区分文件、试卷、题目、知识点四种标识，以有效的题目与知识点关联去重，通过 MyBatis 查询 MySQL 得到不同题数与不同卷数。每次发布绑定输入批次和分析版本，Redis 按发布版本缓存结果。
4. **接入 React。** 在现有课程页提供分析入口、阶段与失败反馈、章节目录、频次排行、证据明细和待核对入口。前端读取同一发布版本，沿用 M1 的来源预览。

## 完成判据

负责实现的开发者按 M2-01～08 编写并执行用例。分题计数、去重和排序做规则测试，Agent 证据校验、事务发布、重试和缓存回退做集成测试。三卷样例必须从实际课程页导入并运行真实分析，逐项核对人工答案中的章节归属、题数、覆盖卷数及原题位置，同时回归 M1 导入和预览。仅展示预填数字无法验收这一流程。

固定样例要求逐项一致。建议用另一份未参与调试的授权或自制卷，分别记录误配、漏配、待核对数及分析耗时。真实课程的准确率与速度门槛待有代表性样本后商定。交付时附运行步骤、实测结果、README 更新及 GitHub 发布安全检查结果。
