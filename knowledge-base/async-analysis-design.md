# R2 异步分析与安全重试 · 需求、实施与验收

2026-11-28 用户审阅后要求开始开发。已选技术为 RocketMQ 和 Redisson。改造前，`AnalysisApi.analyze` 在同步请求内取批次材料、等待 Python、校验出处并在 MySQL 事务中发布，删课保护使用进程内计数。R2 从学生点击“分析本批资料”开始，终点是工作台显示可追溯的发布版本或明确的失败原因。

## 用户可观察的行为

提交后返回可查询的任务号。刷新页面可以按课程和批次找回任务。网络重试沿用同一请求标识，用户主动重新分析使用新标识。任务最多发布一个结果版本。排队、运行或失败期间，学生可以继续阅读、导出上一次发布的结果。

| 编号 | 产品行为 |
| --- | --- |
| R2-01 提交与找回 | 沿用现有批次就绪规则，所有文件均已结束且至少一份可用时允许分析。登记成功即返回任务号，页面显示等待投递、已排队、分析中、等待重试、已发布或失败。刷新、重开页面或切课返回后，按课程与批次从服务端找回任务。 |
| R2-02 重复操作 | 同一次点击、连点及响应丢失后的重发都找回原任务。同课同一请求标识用于另一批次时返回 409。同课一次受理一个未结束任务；不同页面用新标识同时提交时提示已有任务及其批次。任务结束后，主动点击“重新分析”才能新建任务，成功后得到新版本。 |
| R2-03 固定分析输入 | 受理时固定本批参与分析的文件、解析产物版本及分析所需课程信息。旧批次缺少不可变产物标识时，保存本次使用的正文片段和可解析的历史出处。排队、重投或接管均使用这份输入。继续沿用 R1 的整批统计和原页定位规则。 |
| R2-04 可恢复且只发布一次 | 消息可以重投，计算可以重做；同一任务成功时只有一个完整版本，失败时新增版本数为零。暂时无法投递时保留已受理任务并显示等待原因。分析执行失败按有限次数重试；非法出处等确定性错误直接失败，给出学生能采取的下一步。 |
| R2-05 继续复习 | 等待、分析或失败期间，工作台标清当前阅读版本，出处、笔记、待办、Markdown 导出继续可用。首次分析尚无旧版时显示任务状态。成功后目录、排行、证据一起切换；另一门课迟到的轮询响应不能覆盖当前页。 |
| R2-06 课程隔离与删课 | 任务查询和批次归属都按课程校验，跨课返回 404。自建课程有任何未结束的分析时，删除返回 409。任务进入终态后按既有删课规则清理任务及相关记录。 |

## 实施方案

1. **登记任务。** 新增课程和批次范围内的异步提交与查询接口，受理成功返回 HTTP 202。浏览器在首次发送前保存请求标识，响应丢失后沿用。后端在 MySQL 事务内锁定课程记录，先判重，再校验批次和当前任务，写入固定输入、任务和待发送事件。删课使用同一课程锁检查非终态任务。课程内请求标识设唯一约束。
2. **投递和执行。** 后台把待发送事件投递至 RocketMQ，消息携带任务 ID。发送确认丢失时允许再次投递。消费者读取任务状态，已完成的任务直接确认；待执行任务通过 Redisson 的任务级锁协调执行，并用 MySQL 条件更新登记本次执行令牌。按本机处理能力限制消费者并发。
3. **安全发布。** 消费者校验分析产物后，在同一 MySQL 事务中检查执行令牌、发布快照并把任务标记为成功。按任务 ID 对发布版本设唯一约束，事务成功后才确认消息。过期执行者的写入应回滚。在执行权过期并转移时允许重新计算。
4. **恢复和用户反馈。** Broker 暂时不可用时保留待发送记录；Redisson 所需的 Redis 不可用时暂停领取新分析，恢复后继续。短暂故障有限重试，达到上限后将失败原因同步到任务状态。对执行者失联和超期运行的任务提供超时接管，避免状态永久停留在运行中。
5. **迁移入口并交付。** 工作台改为提交后轮询，读结果仍走已有发布接口。旧同步 POST 在兼容期复用同一任务执行与发布流程，保留其成功响应和错误契约；无请求标识的旧调用按一次新操作处理。旧版快照允许没有关联任务。更新依赖、Compose、常规及独立试用启动步骤，并迁移依赖同步响应的浏览器用例。先贯通一次真实提交到发布，再接刷新和旧入口，最后注入故障验收。

限流、全局积压上限与流量退避归 R5，单文件的 OCR 阶段恢复归 R6。本期恢复粒度为一次分析任务。单机默认每个实例运行一个分析消费者，每个任务最多执行三次（含首次）；基础设施离线等待不消耗执行次数。超时按现有 Agent 配置设置，执行租期为 Agent 超时加 30 秒，短暂执行故障间隔 2 秒后可重试。

## 验收用例

| 需求与验证层 | 前置条件与操作 | 通过条件 |
| --- | --- | --- |
| R2-01、R2-02 接口与浏览器 | 用延迟返回的 Agent 提交就绪批次，丢弃首次提交响应，连点、刷新并重发；终态后主动重新分析 | Agent 放行前已能查询任务；重发得到相同任务号，数据库只有一个任务及一条发布记录。主动重分析取得另一任务号，成功后总计两个版本。全失败或仍在解析的批次不受理。 |
| R2-02、R2-06 并发集成 | 两页用不同标识同时提交同一课程，再将原标识用于另一批次 | 同课最多一个活动任务，冲突响应可定位原任务；标识与批次冲突返回 409。 |
| R2-03 R1 回归 | 暂停消费，提交后重新识别一份文件，再恢复消费；覆盖新版产物及升级前旧批次 | 首个任务的题数、卷数和逐题出处与提交时输入一致；主动重分析才使用更新材料。逐条打开原页核对。 |
| R2-04 投递集成 | 任务落库后、发送前停 Broker，再重启 Java 和 Broker | 页面能找回原任务，服务自行补投，最终成功，按任务号查询恰有一个版本。 |
| R2-04 执行与发布集成 | 分别在运行中断开 Redis 并让另一消费者接管、在事务提交后确认消息前终止消费者 | 恢复后任务有终态。迟到执行者无法改写状态、命中明细或版本；已成功任务的重投读回同一版本。 |
| R2-04、R2-05 规则与浏览器 | 已有版本和笔记，注入持续执行超时、非法出处；等待及失败时打开出处、读写笔记并导出 | 临时执行故障达到配置次数后失败；非法结果首次即失败。两者新增版本均为零，页面显示原因与重新分析入口；旧版本号、原页和导出内容一致，保存的笔记可重读。 |
| R2-05、R2-06 多课端到端 | A 提交后切到 B，延迟 A 的状态响应，再切回；以 B 的路径查询 A；分别在待投递、排队、运行、等待重试时删 A | B 页面只显示 B 的数据；切回 A 找到原任务。跨课查询为 404；各非终态删课均为 409；终态后可正常删除自建课，B 的笔记与版本可读。 |
| R2-01、R2-05 升级回归 | 从已有 R1 批次、快照和笔记升级，调用默认课程和显式课程旧入口，再用新页面分析 | 旧客户端仍读到约定的结果或错误；升级前的出处、待办、笔记、导出可读，增加一个新任务后新旧数据归属正确。 |

## 2026-11-28 本机实测

试用环境使用独立 MySQL 8.4、MinIO、Redis 7.4、RocketMQ 5.3.2、Redisson 3.45.1、JDK 21 和无头 Edge。V7 使用任务行的状态和下次投递时间保存待发送事件。新批次保存解析产物标识，旧批次缺少标识时保存片段。终态释放任务输入，保留请求、执行次数、原因和版本关联。

| 故障注入与观测 | 实际结果 |
| --- | --- |
| V5 发布并记笔记 → V6 增加带产物标识的发布版本 → V7 升级。分别在 Broker 离线时提交两种批次，重新识别 PDF，重启 Java 后恢复投递。 | 两个任务的题数、卷数、排行、来源均与各自基线一致，每条出处可读，PDF 预览摘要一致。旧笔记与导出保留，主动重分析改用新产物。 |
| 任务 `8b9ed983-f48c-4765-ba80-19eb63d2d499` 在 MySQL 提交后、RocketMQ 确认前强制退出 Java，再启动消费者。 | 在新进程捕获相同任务的真实重投，执行次数仍为 1，数据库有且仅有一个发布版本。 |
| 任务 `033688ad-c805-4d27-8521-b7abefacafd6` 在检查 Redis 锁后、进入发布事务前暂停。断开 Redis，启动第二个消费者并恢复 Redis，等其发布后再放行原执行者。 | 共执行 2 次，仅发布 1 个版本。旧执行者结束后，任务状态和版本号均与接管者提交的结果一致。 |

浏览器与接口故障用例 `r2-tests/tasks.mjs` 也已通过。首次提交响应丢失后，刷新和重发均找回原任务。故意延迟 A 课轮询并切换到 B，B 未显示 A 的任务，切回 A 后可继续查看。并发提交返回一个 202 和一个指向相同任务的 409。Redis 离线等待时执行次数为 0；非法出处执行 1 次失败，持续超时执行 3 次失败，两者新增版本均为 0。待投递、排队、运行、等待重试时删课均被拒绝，终态后正常删除。旧版笔记、出处及 Markdown 导出通过回读核对。

回归覆盖 M2 规则、真实浏览器与同步 502/504，M3 学习和导出，M5 界面专项，M6 双课及重启。Python 在本地语义模型开启时通过 12 个用例。Java 规则测试覆盖批次就绪条件、删课和复习计划。

命令及旧版 JAR、样本和试用端口说明见 [README 的 R2 验收步骤](../README.md#r2-后台分析与恢复)。升级和消费者故障由 `r2-tests/recovery.mjs` 复现。
