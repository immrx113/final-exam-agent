# M5 个人电脑试用 · 需求与验收

学生按一份 Windows 启动说明打开本机课程页，把一门课的课件、讲义和试卷分别导入，从高频考点找到原题，保存复习进度，最后下载与当前页面一致的 Markdown。M5 以这次完整试用及中断恢复作为交付目标。

已确认的统计、学习、导出和视频规则沿用[首版需求](personal-review-requirements.md)、[M2](m2-acceptance.md)、[M3](m3-acceptance.md) 和 [M4](m4-acceptance.md) 各自已核验的范围。[架构草案](architect.md)中的 M5 条目提供规划背景。以下试用方案与通过条件已于 2026-11-25 经用户确认。

## 怎么做、怎样算通过

| 编号 | 从哪里验证、怎样操作 | 通过条件 |
| --- | --- | --- |
| M5-01 本机启动 | 在 Windows 的独立试用环境，按 README 准备依赖和本地配置，从仓库根目录启动，打开课程页，再正常停启一次。 | 记录实际使用的依赖版本、解析方式与命令。启动不依赖开发者私有工作目录；照说明可进入课程页，停启后能重新打开同一门课。 |
| M5-02 导入与依据 | 建议用一套自制《数据库原理》完整课程样本，含幻灯片、PDF 讲义、三份卷，其中有扫描页。先人工标出教学出处和每个考点对应的卷、题、页，再从三个上传区导入。 | 同一知识点保留两个教学出处；讲义练习不计入真题。“函数依赖 4 题 · 1/3 份卷”排在“关系代数 3 题 · 3/3 份卷”前；逐题可回到正确原页，改名重传同卷后数字一致。存疑内容可回看，有有效卷时隐藏零命中项。 |
| M5-03 学习与导出 | 从上述结果打开参考计划，查看顺序理由，勾选待办并保存笔记，重新打开后实际下载 Markdown。 | 勾选和笔记可读回并继续编辑。下载文档的版本、正命中知识点、题数、覆盖数及逐题依据与页面逐项相符，排除零命中、个人笔记和完成状态。 |
| M5-04 视频 | 在同一课程页分别核对公开搜索、课程 BV 目录后备和视频服务失败。实际点开推荐链接。 | 有相关结果时整门课展示 1～3 条，排序和讲次定位沿用 M4。记录每条实测路径使用的来源。搜索若再遇 HTTP 412，单列为受限；后备目录成功只计入后备路径。视频失败时仍能复习、保存和导出。 |
| M5-05 中断与恢复 | 先发布一版并保存笔记，追加材料。在新分析进行中重启 Java，另一次让 Agent 超时，然后恢复服务并重试同一批次。单独清空专用试用 Redis 的课程缓存并再次读取。 | 重启后页面可继续或重试该批次；允许手动重试，无需重新上传。新版发布前可查看和导出旧版，失败不覆盖它。成功后版本、计数和依据一起更新，无重复计数，同一知识点的笔记及勾选保留。清缓存前后同版结果一致。 |
| M5-06 质量与交付 | 用固定样本对照人工答案，再用一份未参与调试的自制或获授权试卷抽查。记录材料规模、解析及分析耗时、误配、漏配、待核对页和视频限制。 | 固定样本的题数、覆盖数、原题位置逐项一致。另卷给出查准率、召回率和待核对比例及各自分母；耗时注明机器及输入规模。首次试用先建立基线。交付附复现步骤、逐项结果、未通过或未执行项及原因。 |

## 实施顺序与交付物

1. 先备齐样本和人工答案，复用已有 M1～M4 用例与启动脚本，整理一条能从头执行的 Windows 路径。
2. 在独立试用数据上走通 M5-01～04，然后做 M5-05 的故障演练。优先修复阻断启动、证据定位、数据恢复或导出的缺陷，修复后重跑相应用例及受影响回归。
3. 最后用独立试卷完成 M5-06，整理 README 启动说明和逐项验收记录。交付前检查拟发布文件中的凭据、本地配置、日志及课程材料分享权限。

建议本轮集中在现有单人、本机、一门课的流程。安装程序、多用户部署和新增视频平台另行规划。真实课程泛化质量及耗时阈值，留待取得代表性样本后确定。
