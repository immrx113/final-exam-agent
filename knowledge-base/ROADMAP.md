# 期末复习助手 · 六项改造开发路线图

规划日期为 2026-11-27。六项改造已获用户采纳，需求二已选定 RocketMQ 和 Redisson。以下阶段顺序、接口草案和验收方法为建议，立项时六项均待开发。2026-11-28 已在本机验收前三项改造。实测范围见 [R1 增量解析](r1-incremental-parsing.md)、[R2 异步分析](async-analysis-design.md)和 [R3 考点修正](r3-topic-corrections.md)。每期交付一段能从学生工作台实际操作的流程。

## 六项改造

| 编号 | 学生遇到的问题 | 本轮交付与边界 |
| --- | --- | --- |
| R1 增量解析 | 给已处理的课程补一份卷，旧文件随新批次再次转换、渲染或 OCR。 | 同课跨批次复用已成功的正文、预览与定位信息，仅解析新增或失效的文件。每次发布仍按本批完整材料重新统计。 |
| R2 异步分析与安全重试 | 分析时刷新、掉线或重复点击，很难判断上一次是否完成。 | 用 RocketMQ 投递任务，Redisson 协调同一任务的执行，MySQL 保存请求、状态和发布版本。可查进度、可恢复、同一次请求至多发布一个版本；主动重新分析产生新任务。 |
| R3 考点校验与人工修正 | 多考点题只命中一部分时，漏配可能直接进入频次、计划和导出。 | 按作答要求检查关联；待确认部分可定位到原题。学生能增删题目与考点的关联，确认后发布修正版，保留旧版本和修正依据。 |
| R4 分片上传与断点续传 | 接近传完时连接中断，整份文件需要重传。 | 显示文件进度，支持暂停、恢复、取消与完整性校验；成功合并后沿用现有文件登记与批次入口。首轮沿用 50 MB 单文件上限，可在本机模拟弱网验收。 |
| R5 限流与退避重试 | 多页同时提交或轮询、上游抖动时，重复请求挤占正常复习操作。 | 对新分析请求使用令牌桶并限制积压量；限制 OCR 和分析并发；对网络瞬时故障有限退避，对视频来源的持续限制使用课程目录后备。 |
| R6 阶段级恢复 | 长扫描卷处理到后半程中断，重启后会从头处理该文件。 | 保存转换、渲染、正文识别的成功产物和输入版本。逐页执行的路径支持页级恢复；整文档调用的 MinerU 按已完整落盘的阶段恢复。 |

R1 解决“新批次复用已经完成的文件”，R6 解决“继续上次中断的同一文件”。R2 的重试单位是一次分析任务，R4 的重试单位是一次上传中缺失或损坏的分片。这些单位应分别计数和验收。

## 阶段顺序与验收

建议主线为 **基线 → R1 → R2 → R3 → R4 → R5 → R6 → 综合验收**。顺序兼顾单人实施与可独立交付。技术上 R4 在基线完成后即可开展；R5 依赖 R2 暴露队列状态，R6 依赖 R1 的产物标识和完整性检查。R3 使用 R2 的版本发布机制。

### 阶段 0 · 建立可对照的试用基线

- 用独立试用库准备两门课程、13 份可复用材料和 1 份新增卷，另备多考点题、独立标注试卷、接近 50 MB 的文件和长扫描 PDF。记录各样本对应的场景与人工答案。
- 从浏览器分别记录上传、等待解析、OCR、等待分析、执行分析和发布耗时，以及读取旧结果、保存笔记的响应时间。记录机器、解析方式、模型配置、文件大小和页数。
- **完成判据**：能在相同配置重放“首次导入”和“追加一卷”，得到一致的题数、卷数与证据位置。历史 M5 六文件样本记录为解析就绪 18.833 秒、分析结果 0.200 秒，仅用于选取观测点。[M5 验收记录](m5-acceptance.md)

### 阶段 1 · 增量解析（R1）

- 在 MySQL 登记文件摘要、文件类型、解析方式、工具及配置版本和产物引用；MinIO 保存可复用预览。批次引用具体成功产物；用户主动重新识别或配置变化时生成新产物。存量批次沿用原有预览入口。
- 将复用判断接入上传后的文件处理队列。命中时校验产物完整性；缺件或校验失败只重建受影响文件。课程归属由业务层校验。
- **完成判据**：已成功处理 13 份后追加第 14 份，解析器实际只处理新增文件；与冷启动全量解析的题数、卷数和逐题定位一致。强制重识别后旧版本仍能打开原出处。记录两条路径的 OCR 页数及耗时。

### 阶段 2 · 异步分析与安全重试（R2）

- 先交付最短流程：提交 → MySQL 事务登记任务及待发送事件 → 返回任务号 → RocketMQ 消费 → Redisson 按任务 ID 加锁 → MySQL 事务发布 → 页面读到版本。前端支持刷新后找回本课任务；建议以新增异步接口迁移现有调用方，逐项核对旧版客户端和测试依赖。
- 再补故障路径：同一请求标识返回原任务；执行令牌和任务到版本的唯一约束防止迟到结果写回；Broker 恢复后补投；失败达到重试上限时页面可见。将排队、运行和待投递任务纳入删课保护；更新 Compose、启动脚本与 README。
- **完成判据**：分别在任务落库后停 Broker、消费中断开 Redis、发布成功后但确认消息前停消费者。恢复后任务有终态，同一任务至多发布一个版本。旧版阅读、笔记和导出仍可用；主动重新分析能产生新版本，跨课查询被拒绝。第二项的详细流程见[异步分析需求与实测](async-analysis-design.md)。

### 阶段 3 · 考点校验与人工修正（R3）

- Python 输出每个作答要求的关联和来源，Java 校验候选与已确认关联。把“已识别主键、另一个作答要求可能涉及外键”呈现为可处理的待核对项。沿用原题的计数单位，同题同考点最多计一次。
- 工作台支持核对原文、增删关联、确认并发布。修正版关联原版本；多人次或多标签页基于旧版提交时提示核对最新版本。下游统一读取选中版本的频次、计划、待办和 Markdown。
- **完成判据**：用“主键显式、外键隐含”的复合题验证，学生补上外键后只增一次命中，原页定位正确，新旧版本结果可分别核对。在独立标注卷上同时报告查准率、召回率、待核对比例及分母；单列新增误配，由样本结果确定规则阈值。

### 阶段 4 · 分片上传与断点续传（R4）

- 实现课程级上传会话、分片编号与摘要、已接收分片查询、幂等合并、取消和过期回收。服务端校验分片及总大小、完整文件摘要和格式，最终登记沿用现有去重规则。浏览器恢复时若需重选本地文件，校验为同一文件后续传。
- 工作台逐文件显示进度和失败原因；提交部分成功的材料前，列清成功、失败及将纳入批次的文件。原件登记完成后进入 R1 的解析流程。
- **完成判据**：将 45 MB 文件传至约 90% 时断线，刷新后查询已收分片，只传剩余部分；最终下载内容与原件逐字节一致。重复合并只生成一条文件记录；错误分片、超限文件与跨课会话被拒绝；取消后临时对象可回收。

### 阶段 5 · 限流与退避重试（R5）

- 将“每段时间能接多少新任务”“允许积压多少任务”“同时能跑多少重任务”分别配置。已受理任务的重复提交优先返回原任务；新任务超限时返回可识别的暂缓状态及建议重试时间。
- 批次轮询和可恢复的外部请求使用有上限的指数退避与随机抖动。成功后恢复正常节奏；视频持续受限时提示原因并使用已有目录后备。记录队列长度、等待时长、限流数和实际重试数。
- **完成判据**：在固定配置下，同时提交超过队列上限的独立任务、重放同一请求，并打开旧结果和保存笔记。验证队列有界、重复请求可查、并发不超限、旧版操作成功。记录普通操作 P95 和样本数，与阶段 0 同机对比。用模拟源验证临时故障后成功、持续拒绝后停止自动重试两条路径。

### 阶段 6 · 长文档阶段级恢复（R6）

- 先接入长扫描 PDF 的逐页渲染和 OCR，再覆盖 Office 转换及整文档 MinerU 的阶段边界。以文件摘要、输入产物、配置版本、阶段和页号登记完成记录。只在产物写入并通过校验后标记完成；恢复时从首个缺失或失效的依赖开始。
- **完成判据**：在百页测试卷第 80 页处理期间终止服务，重启后复用此前已确认的页；记录实际重做页数。模拟一页产物损坏和一次配置变更，分别验证修复范围。完整跑与恢复跑的页序、文本和证据定位一致。整文档 MinerU 场景单列可恢复的阶段及重做成本。

### 综合验收与交付

从已有数据库升级，在两门课程中走通“续传 → 补卷 → 解析恢复 → 排队分析 → 核对漏配 → 下载修正版”。过程中重启服务、制造重复投递并切课，检查旧版证据、权限隔离、笔记、完成状态和导出。性能记录分开报告提交响应、实际等待和执行耗时。

由各阶段实现者按[编码规范](../coding-standards/README.md)执行规则、存储集成与浏览器测试。优先复用 [M2 分析验收](m2-acceptance.md)、[M3 学习及导出](m3-acceptance.md)、[M4 视频降级](m4-acceptance.md)、[M5 中断恢复](m5-acceptance.md)和[多课程验收](multi-course-requirements.md)。每阶段随可用功能更新 README、记录实测与未测项，并检查拟发布文件中的凭据、日志及课程材料。队列容量、分片大小、退避上限和性能目标用基线与目标电脑的实测值确定。
