# M4 课程参考视频 · 需求与验收

学生在《数据库原理》的复习页看到与当前优先知识点有关的 B 站视频，知道每条推荐对应哪个知识点，点击即可到达相应的一讲或整套课程。

已确认的产品口径是整门课推荐 1～3 个相关视频，依次按播放量、点赞数、收藏数降序。视频推荐归属 M4。以下触发、匹配、降级和重试细节作为本轮验收条件。[首版需求第 5 节](personal-review-requirements.md) · [M3 范围](m3-acceptance.md)

## 学生看到什么

- 分析版本成功发布后，课程页立即可用，视频区单独显示检索进度。建议每个新发布版本自动检索一次，刷新页面读取已有结果。有效卷下只采用有命中的可见知识点，只有教学材料时采用已有计划中的可见点。无可见点时提示暂无可推荐的知识点。
- 每条显示标题、对应知识点、链接指向和三项热度。课程和讲次标题能共同说明相关性时，优先直达匹配的一讲。目录不可读但整套课程标题相关时，链接到整套并标明。无关的高播放视频应被过滤。
- 多个知识点对应同一播放目标时合并成一条，保留各匹配点。真实相关结果只有一条就展示一条。检索成功却无匹配时显示空结果。超时或请求被拒时显示失败原因，提供重试入口。
- 建议同批按同层级且候选均取得的指标依次比较，缺失显示“未取得”，真实零值显示 0。分 P 使用整条视频数据时标注“整条视频”。没有共同可比指标时，建议按匹配到的知识点在计划中的顺序展示，并说明热度无法比较。

## 实施顺序

1. 先测候选发现。在开发环境用课程名和知识点名从公开数据源搜索，记录能否找到候选，再独立验证目标链接、分 P 目录和热度字段。公开搜索受限或没有相关结果时，允许使用手工维护的课程 BV 目录，读取实际讲次并筛选，展示候选来源。公开关键词发现与目录后备分别验收。
2. 在 Spring Boot 复用已发布的版本、计划和知识点标识，发布事务结束后独立检索。对外只发送课程名和知识点名。把数据源访问与相关性筛选、去重、排序分开，以便用固定样例复现结果。
3. 按课程与分析版本保存查询状态和结果，提供读取与重试。在 React 现有课程页展示同一版本的推荐。连续重试复用进行中的查询，旧版本的迟到响应只归旧版本。

## 开发验收

| 编号 | 验证层与操作 | 通过条件 |
| --- | --- | --- |
| M4-01 | 接口与页面：发布有命中试卷、仅教学材料、无可见点三种版本，再刷新 | 分别用可见命中点、计划中的可见点检索，或显示暂无可推荐点。刷新不重复发起外部查询。 |
| M4-02 | 规则与真实链接：输入课程“数据库原理”、知识点“关系代数”，给出有该讲的目录、目录不可读的相关课程及无关热门视频 | 可定位时打开对应讲次；否则只保留标题相关的课程并标明链接范围。无关视频不入选。 |
| M4-03 | 规则：输入重复链接、同一讲匹配两点，以及 0、1、2、4 个不同相关目标 | 重复目标合并；最终分别展示 0、1、2、3 条。空结果有明确提示。 |
| M4-04 | 规则：构造播放量不同、播放量相同、播放与点赞都相同的候选，再加入缺失值、零值及整条视频的分 P 指标 | 分别由播放、点赞、收藏决定顺序。缺失、零值和指标层级如实展示；无共同指标时展示降级理由。 |
| M4-05 | 接口与存储：让旧版本延迟返回，发布新版本；对失败查询连续点击重试 | 新页面只显示新版本结果，同一次重试只执行一次外部检索。 |
| M4-06 | 浏览器：让视频服务超时或拒绝请求，在等待及失败后查看图谱、勾选待办、保存笔记、下载 Markdown，再恢复数据源并重试 | 各复习操作可完成，笔记可重读，下载规则沿用 M3；重试只更新视频区。 |
| M4-07 | 真实数据端到端：从课程分析发布进入复习页，从真实搜索结果点开一条推荐 | 能从课程和知识点发现真实候选并打开正确目标，记录查询条件及指标层级。仅用固定候选通过时，真实检索仍记为待验。 |
