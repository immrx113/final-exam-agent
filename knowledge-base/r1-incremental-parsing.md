# R1 增量解析 · 需求与验收

2026-11-27 用户审阅需求后确认开始开发。“13 份旧材料追加第 14 份”是本阶段的主验收场景。

## 学生操作与范围

学生在当前课程勾选已有材料，添加新卷，沿用“提交处理”。批次清单仍由本次选择决定。页面逐文件显示处理结果，能区分“复用已有解析”和“本次解析”，失败项仍可重试。解析完成后，学生点击“分析本批资料”，使用本批所有可分析材料重新生成统计和出处。未选的旧卷应从这次分析中排除。

改造前，`ImportApi.submit` 按课程和文件集合确定批次；文件集合一变，所有条目都会入队。`Worker.runOne` 对普通入队文件逐份调用解析器，预览按批次保存。`Worker.refreshText` 在原批次更新片段，而 `AnalysisApi` 发布的出处链接指向批次、文件和位置。

本期以一份完整文件为复用单位。分片续传、分析任务异步化、页级中断续跑分别归 R4、R2、R6。

## 实施顺序

1. **先建立可对照样本。** 在独立试用库准备 13 份自制材料和第 14 份新卷，覆盖 PDF、Office、Markdown、图片及需要 OCR 的页面。固定解析与分析配置，记录冷解析全部 14 份的结果。为解析入口、转换、渲染和 OCR 加入可按文件核对的执行记录。
2. **把成功结果保存为可引用的版本。** MySQL 登记所属课程、内容 SHA-256、实际输入格式、解析方式、相关工具与配置版本，以及正文、位置、待核对标记和预览清单。MinIO 保存页图或行预览，图片沿用原件。同内容改名或改变用途时，建议在格式与解析条件相同的前提下复用产物，分析继续使用本次文件名和用途。
3. **在文件出队后、调用解析器前判断复用。** 校验同课候选的片段、位置和所需对象的完整性。命中则绑定产物并就绪。无匹配、配置失效或确定损坏时，仅重解析受影响文件。存储暂时不可访问应显示可重试，避免把连接故障判为对象损坏。写入完整并验过后再提交批次绑定；处理中断留下的半成品不可命中。
4. **固定历史出处。** 沿用 PDF、Office 的“重新识别正文”入口。强制重识别绕过普通复用，成功后为当前批次绑定新的完整产物，失败时保留先前结果。新发布的分析把出处绑定到确切的产物版本。升级时保留旧批次预览地址与已发布链接；缺少可靠配置记录的旧产物继续可读，首次参与新批次时按需重建。配置变化在后续新批次处理时判定；重复提交原清单仍打开原批次。

## 达到什么程度算完成

| 编号 | 验证入口与操作 | 通过条件 |
| --- | --- | --- |
| R1-01 | 浏览器提交 13 份，待全部成功后，勾选这 13 份并补一份新卷 | 新批次有 14 项，13 项显示复用，仅新卷进入解析器。13 项的转换、渲染、OCR 实际执行数均为零。刷新可见相同结果。 |
| R1-02 | 将追加批次与同配置下冷解析 14 份的结果逐项比对；另建一个去掉某份旧卷的批次 | 两条路径的有效卷数、各考点命中题数与覆盖卷数一致，每道题均能打开同一来源内容和页、行或原图。去掉的卷不再贡献题数或证据。 |
| R1-03 | 规则与存储集成测试分别改变名称、用途、文件字节、输入格式和相关解析配置；模拟一份文件缺页图或预览损坏 | 按上述规则命中或失效。单文件损坏仅重建该文件，其他完好且匹配的文件继续复用。原有待核对标记随产物保留。 |
| R1-04 | 发布 A 后主动重新识别其中一份支持的文件；分别验证成功、失败，以及重分析发布 B | 成功时产生新产物，B 的证据可核对新结果；A 及其他已绑定旧产物的批次仍能打开原出处。失败时提示可重试，上次正文和预览可读。 |
| R1-05 | 两门课上传相同文件；在课程 B 尝试读取 A 的预览；在同课重复提交同一清单 | B 首次独立解析，越课读取返回 404。同课重复提交指向同一批次，既有就绪项不会再次执行。 |
| R1-06 | 用升级前保存的批次、已发布链接和笔记验证迁移；在新产物写入途中模拟故障并重启或重试 | 旧链接仍打开原页，笔记与旧版分析可读。未完整写入的产物无法复用；重试成功后，批次每项只绑定一个完整版本。 |

实现者交付时提供浏览器场景、规则与存储集成测试结果，按同一机器、样本和配置列出冷解析 14 份、追加第 14 份两条路径的解析文件数、OCR 页数及从提交到解析就绪的耗时。分析耗时单列。以实际执行次数和结果一致性验收，暂不设固定提速百分比。功能交付时同步更新 README 的追加材料与重新识别说明。
