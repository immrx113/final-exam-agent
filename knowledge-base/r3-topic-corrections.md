# R3 考点校验与人工修正 · 需求与验收

2026-11-28 用户审阅后要求进行 R3 开发。沿用的计数、学习记录、出处和发布约束见 [M2](m2-acceptance.md)、[M3](m3-acceptance.md)、[R1](r1-incremental-parsing.md)、[R2](async-analysis-design.md) 和[多课程需求](multi-course-requirements.md)。

## 学生要解决的问题

自制例题为“指出订单表的主键，并说明为什么订单中的客户编号必须在客户表中存在。”讲义已定义主键和外键。改造前用默认课程规则模式实跑，得到 1 道题、1 个主键关联、0 条待核对。旧 Agent 只把整题无匹配的题送入语义补配。当时的工作台可以打开待核对原文。

R3 的目标是让学生看到第二个作答要求尚待核对，能对照原题补上外键，也能删除已经计入的误配。发布后，每个变化的数字都能追溯到具体题目和修改记录。

## 要交付的行为

| 编号 | 学生可观察的行为 |
| --- | --- |
| R3-01 逐项校验 | 对每道可辨识题保留原题号、各个作答要求、对应原句及来源。一个要求已有可靠命中时，仍检查其余要求。信息不足时显示原因和可选考点，也允许没有候选。候选只有在确认后才计数。题号、卷归属或 OCR 本身存疑的材料沿用既有提示。 |
| R3-02 对照并修正 | 从待核对项或已命中题打开原页或原行。可接受候选、从本版本已有考点中补选（含当前零命中项）、移除误配，或将要求标为已核对且无相应考点。草稿显示增删差异；取消可放弃。首期建议把新建或改名考点、改题号、人工分卷留到后续。 |
| R3-03 确认并发布 | 确认时生成同课程、同批次的新版本，记录父版本、原题、作答要求、增删前后的关联、原文依据和时间。允许先发布已处理的修改，其余疑项继续待核对。工作台可选原版和修正版，分别阅读、核对出处与导出。 |
| R3-04 全部视图一致 | 从所选版本的最终关联统一生成频次、章节目录、参考计划、待办和 Markdown。同题同考点最多一次，同卷多题只增加题数；有效卷总数沿用父版。独立编号且可独立作答的小问沿用 M2 计数；同一道题中的多个要求共享原计数单位。零命中项按 M2/M3 隐藏和排除导出，笔记及勾选沿用课程与稳定考点标识。 |
| R3-05 安全提交与兼容 | 重发同次发布只得到一个修正版。基于过期版本提交时提示冲突，保留本页修改供与最新版核对。建议同课 R2 分析进行中时允许阅读与编辑，暂缓修正发布，任务结束后再核对基版。跨课读写被拒绝。升级前缺少逐项明细的快照可读、可按原规则导出，页面引导重新分析后开启修正。 |
| R3-06 识别质量可衡量 | 在固定例题上逐项对照人工答案，再用未参与调参的独立标注卷比较改造前后自动结果。单列人工修正后的结果，使读者能区分算法改进和人工补正。 |

## 怎么做

1. **先固定题目和预期。** 准备显式与隐含考点并存、背景提及、重复要求、独立小问、跨页续题及无候选样例。标出题目计数单位、每项要求、应计考点和原文位置。同时覆盖数据库默认课与自建课程的匹配路径。
2. **Python 提取，Java 校验。** Python 扩展题目输出，保留每个要求的原句、来源、已命中及候选考点、判定原因。Java 验证引用来自该版本中该题的试卷片段，考点属于本版；保留完整可编辑题目集合，包括零匹配的可辨识题。由最终关联集合按题去重，不从某个排行榜数字上直接加减。
3. **复用版本发布与统计。** MySQL 保存修正所需明细；在同一事务内核验课程、基版及请求标识，写入修订记录并发布完整快照。沿用基版固定的材料、出处和生成计划所需依据。人工发布复用现有统计与计划逻辑，无需重跑 OCR 或 Python。R2 自动分析仍绑定自己的任务；后续主动重新分析生成独立结果，首期建议由学生核对后决定是否重用此前修正。
4. **接入工作台。** 从现有“待核对”和已命中题共用一个编辑入口，复用页内原文对照。标明正在编辑的版本和待提交修改，发布成功后选中修正版。为原版与历次修正版提供按版本读取和切换入口。失败保留当前选择，便于重试。

## 做到什么程度算完成

| 对应需求 / 验证层 | 前置与操作 | 必须观察到的结果 |
| --- | --- | --- |
| R3-01、02 / Agent 规则、浏览器 | 各用 1 份讲义和 1 份自制卷走实际导入分析流程，使用上面的订单题。查看两项要求，打开第二项原文，选择外键并发布。 | 原版主键 1 题、外键 0 题；第二项可核对并指向该题。修正版两个考点各 1 题、各覆盖 1/1 份卷。仅编辑、取消或保留待核对都不会提前改变已发布数字。 |
| R3-01、04 / 计数规则、存储集成 | 同题两个要求均关联外键，移除其中一个，再移除最后一个；另设同卷两道独立小问、跨页续题和只在背景出现的术语。 | 依次计 1、1、0；独立小问可计 2 题但只覆盖 1 份卷，跨页同一题只计 1 题且两页出处可查。背景术语不计。 |
| R3-02、03、04 / 浏览器、下载、重启 | 两份卷中原本只有甲卷命中外键，在乙卷补上外键；纠正一个误配使其降至零，随后在另一修正版恢复。查看新旧版本并实际下载 Markdown。 | 外键覆盖从 1/2 变为 2/2。排行、目录、计划、待办和下载逐项与所选版本一致；降至零的项隐藏，再次可见时恢复原笔记和勾选。重启后可核对各版差异、原题位置及旧版下载。 |
| R3-03、05 / 服务与数据库集成、双页浏览器 | 双页从同一基版编辑；发布响应丢失后重发、另一页提交旧版、事务中途失败、R2 任务进行中尝试发布、切课或提交其他题的证据。用 V7 旧快照升级后重开。 | 同次成功请求仅一个子版本，过期提交得到 409 且草稿可核对，事务失败新增版本为零。活动分析期间按约定暂缓，跨课访问返回 404，错题证据被拒绝。旧快照可阅读，重新分析后可进入修正流程。 |
| R3-06 / 独立卷评测 | 先冻结规则和阈值，再按同一材料、配置和人工标注对比 R3 前后。 | 以去重的“题目－考点”对报告查准率（正确自动命中 / 全部自动命中）、召回率（正确自动命中 / 全部人工标注命中）；以去重的题报告待核对比例（有待核对要求的题 / 全部可辨识题）。列原始分子分母、漏配和新增误配明细；分母为零标为不适用。固定样例须逐项符合预期，真实课程的百分比目标待有代表性基线后商定。 |

实现者负责执行上述用例并回归 R1 历史出处、R2 幂等发布、M2 计数、M3 学习及下载和 M6 课程隔离。功能验收时更新 README 的实际操作方法，并记录样本、运行配置、结果与未测范围。

## 2026-11-28 本机验收

- Windows、Edge、真实 MySQL、Redis、MinIO 与 RocketMQ。V7 服务先发布自制样卷，升级 V8 后比较原快照及 Markdown，并确认旧版修正入口会提示重新分析。使用工作台上传订单题，主键命中 1 次，隐含外键在核对前为 0；从待核对项选中外键并发布后，两者各计 1 次。同一题对同一考点的两个关联依次撤销，命中数依次为 1、1、0。两份卷上的补正确认覆盖从 1/2 增至 2/2。
- 在独立测试数据库中丢弃首次成功响应、从第二页面提交旧基版、在事务最后写入修正标识时注入故障。重发得到同一版本，旧页收到 409 且保留草稿，失败事务新增 0 个版本。跨课程读写返回 404，越界证据和考点返回 400。自动分析进行中修正发布返回 409，重新分析从原材料生成新原版。重启 Java 后比对历史版、下载内容、原文及学习记录。
- [独立标注卷](../r3-tests/holdout.py)含 6 道题，共 8 个题目－考点对。沿用既有语义阈值。规则模式与离线 BGE 模式在这份卷上的结果相同。旧版与 R3 自动结果都漏掉第 3 题的外键和第 5 题的死锁，新增误配为 0。R3 将第 3 题余下的要求列入待核对，第 2、4 题也增加了需要阅读的提示。评测使用自制样本。
