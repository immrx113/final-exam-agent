# 项目编码规范

## 需求完成后的 README 维护

检查仓库根目录的 `README.md`。如果需求改变了用户可用的功能、安装或启动步骤、配置项、使用方法或已知限制，在同一次改动中更新相关说明。README 中的命令和配置示例应与当前实现相符，示例值使用占位符。

## GitHub 发布安全检查

每个需求开发完成后，检查本次拟上传的变更。范围包括待推送提交、已暂存和未暂存的改动，以及准备纳入版本控制的新文件。检查代码、配置、测试数据、文档和附件中是否有以下问题。

- 真实的 API 密钥、令牌、密码、私钥、会话凭据或含凭据的连接字符串。
- 个人信息、内部地址、真实日志或数据导出，以及受分享权限限制的课程资料。
- 可能误上传的本地配置、调试输出和数据库文件，或会暴露数据的默认配置和访问权限。

在交付说明中写明检查范围和结果。有问题时，在推送前提示文件位置、风险和建议处理方式。引用问题时使用脱敏描述。如果检查通过，说明在已检查范围内未发现问题。如果有文件无法检查，指出未覆盖的内容。
